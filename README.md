# دفء | منصة التبرع بالملابس

منصة فريق دفء التطوعي لاستقبال التبرعات بالملابس في سلطنة عُمان: موقع عام عربي (RTL) بتجربة تبرع بسيطة بدون تسجيل، ولوحة تحكم آمنة لإدارة الطلبات والمواعيد والمتطوعين.

> «دفءٌ منك… وأثرٌ يبقى» 🤎

## ما الذي يتضمنه المشروع

**الموقع العام**
- الصفحة الرئيسية (Hero برسم أصلي، عبارات تحفيزية متغيرة، عن المبادرة، خطوات التبرع، «أثر دفء بالأرقام» من بيانات حقيقية فقط).
- نموذج تبرع كامل: المحافظات الإحدى عشرة وولاياتها (63 ولاية)، أرقام عُمانية (+968)، خريطة اختيارية وتحديد الموقع الحالي بإذن المستخدم، فئات وكميات وحالة الملابس، حتى 5 صور (تُضغط في المتصفح)، الوقت المفضل، الموافقة على الخصوصية.
- لا تظهر رسالة النجاح إلا بعد تأكيد قاعدة البيانات، مع رقم طلب مثل `DF-26-00042`.
- «متابعة تبرعي» برمز تحقق لمرة واحدة يُرسل برسالة نصية إلى الرقم المسجّل في الطلب.
- عن المبادرة، كيف أتبرع، تواصل معنا، سياسة الخصوصية، صفحة 404.

**لوحة التحكم** (`/admin`، غير ظاهرة في قائمة الموقع)
- دخول بالبريد وكلمة المرور (Supabase Auth)، استعادة كلمة المرور، دعوات فقط (لا تسجيل عام).
- ثلاث صلاحيات: مشرف عام، مشرف، منسق متطوعين — مطبّقة في الخادم وقاعدة البيانات (RLS + دوال SQL).
- نظرة عامة بإحصاءات ورسوم بيانية حقيقية، جدول طلبات مع بحث وتصفية وترتيب وتقسيم صفحات، صفحة تفاصيل كاملة (خريطة، صور خاصة بروابط مؤقتة، سجل الحالات، ملاحظات داخلية).
- واتساب برسالة جاهزة (يفتح المحادثة فقط؛ الإرسال يدوي)، اتصال هاتفي، تحديث الحالة، تحديد/تعديل/إلغاء موعد الاستلام مع منع تعارض مواعيد المتطوع، إسناد المتطوعين.
- تقويم الاستلام، المتطوعون، مركز الإشعارات (تحديث فوري عبر Realtime)، التقارير وتصدير Excel/CSV (مع تسجيل كل تصدير)، إدارة العبارات التحفيزية، إعدادات الموقع، إدارة الحسابات والصلاحيات، حذف البيانات الشخصية للطلبات المغلقة.

## التقنيات

Next.js 15 (App Router) · TypeScript · Tailwind CSS 4 · مكوّنات بنمط shadcn/ui · Lucide · Motion · React Hook Form + Zod · Recharts · Leaflet/OpenStreetMap · Supabase (PostgreSQL, Auth, Storage, Realtime) · ExcelJS · Vitest.

## البدء السريع

```bash
npm install
cp .env.example .env.local      # ثم املأ القيم
npm run dev                     # http://localhost:3000
```

ثم اتبع **[DEPLOYMENT.md](DEPLOYMENT.md)** لإعداد Supabase وإنشاء أول مشرف عام والنشر، و**[TESTING.md](TESTING.md)** للاختبارات.

## هيكل المشروع

```
src/
  app/(site)/          الصفحات العامة
  app/admin/(auth)/    الدخول واستعادة كلمة المرور
  app/admin/(panel)/   لوحة التحكم + server actions
  app/api/             إرسال التبرع، المتابعة برمز التحقق، التصدير
  components/          brand · site · donate · track · admin · ui
  lib/                 التحقق، الأرقام العُمانية، الأمان، Supabase، الثوابت
supabase/
  migrations/          الجداول، الدوال، RLS، التخزين، البيانات الأولية
  tests/               اختبارات أمان وسير عمل قاعدة البيانات
scripts/               إنشاء أول مشرف عام، مهمة الاحتفاظ بالبيانات، اختبار القاعدة
tests/                 اختبارات الوحدات (Vitest)
brand-source/          نسخة الشعار الأصلية كما رُفعت
```

## ملاحظات مهمة

- **الشعار**: يُعرض كما هو دون إعادة رسم. أُزيل فقط شريط أسود بعرض 4 بكسل في أسفل الصورة المرفوعة (أثر لقطة الشاشة)، والنسخة الأصلية محفوظة في `brand-source/`. أيقونة المتصفح قصّ مباشر من الشعار.
- **لا توجد بيانات مختلقة**: الإحصاءات من قاعدة البيانات فقط، ومعلومات التواصل وحسابات التواصل الاجتماعي فارغة حتى يضيفها المشرف العام من الإعدادات.
- **خدمات تحتاج إعدادًا منك**: Supabase (إلزامي)، ومزوّد رسائل SMS (Twilio) لميزة «متابعة تبرعي». بدون SMS تعرض الصفحة رسالة صادقة بأن الخدمة غير مفعّلة بعد.
